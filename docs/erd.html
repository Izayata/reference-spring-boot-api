Data dictionary

MyUser

Authentication identity: login credentials and role.

1:1 Customer · 1:N PasswordResetToken

Customer

Order-facing profile: personal details, billing and shipping addresses.

owns FK → MyUser · 1:N Order

Food

A menu item: name, price, category, and where it can be bought.

M:N Allergen · M:N Ingredient

Allergen

Read-only reference data used to tag menu items.

M:N ← Food

Ingredient

Read-only reference data used to tag menu items.

M:N ← Food

Order

A placed order. Snapshots personal details, shipping address, and item prices at order time.

M:1 Customer (nullable) · 1:N OrderItem

OrderItem

A line item: food reference, quantity, and a price snapshot.

M:1 Food · M:1 Order

PasswordResetToken

Single-use, time-limited reset token with a dual-hash lookup/verify design.

M:1 MyUser

EmailOutbox

A queued, retryable email. Deliberately denormalized.

no relationships — plain recipientEmail string

Reading notes

Guest orders

Order.customer_id is nullable — a null FK means the order was placed without an account, not a data-integrity gap.

Snapshotted fields

Order.personalDetails, Order.shippingAddress, and OrderItem.orderItemPrice are copies taken at order time, so later profile or menu-price edits never rewrite history.

EmailOutbox is excluded

It stores recipientEmail as a plain string with no foreign key, so it has no place in a relational diagram — it's queue state, not domain data.

shippingAddresses isn't a boxed entity

It's a JPA @ElementCollection of the Address value object, persisted to its own SHIPPING_ADDRESSES table — shown as an annotated field on Customer rather than a separate entity with a relationship line.
